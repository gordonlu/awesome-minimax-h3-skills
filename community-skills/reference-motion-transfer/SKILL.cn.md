# Reference Motion Transfer · 动作参考迁移

当用户想把一段视频里的**动作**搬到**另一个主体**身上时使用本 Skill ——「让我的角色跳这段舞」「让吉祥物模仿这个手势」「把这个运镜用到我的产品上」。动作来源是参考视频；迁移目标是角色图片、文字描述，或两者。

核心原则：**先分析动作，再动笔；一次生成只用一个动作来源；把模型容量花在动作保真上，而不是花哨场景上。**

本 Skill 通过 `h3-prompt-writing` 构建提示词，严格遵循其指南：T2VA / I2VA / FL2VA / L2VA 读 `base-en.txt`，Ref2VA 读 `ref-en.txt`。字段名、段落顺序、标签与计时记号以指南为准，不得自行发明。

---

## 1. Trigger · 何时调用

满足以下任意一条时使用：

- 把参考视频中的舞蹈、手势组合或身体动作迁移到新角色身上
- 让吉祥物 / 产品 / 生物模仿真人的动作
- 把参考片段的运镜复制到新场景
- 各种语言的「同样动作、不同主体」需求
- 对时机与身体力学有要求的动作风格迁移

以下情况**不要**使用：

- 只想要画面的*风格*（无动作的调色/质感迁移）——那是风格任务，不是动作迁移
- 想剪辑、续写原参考视频——那是 `video editing` / `video continuation`
- 未经授权让真实可识别的私人做出未做过的动作——违反 H3 使用政策（AUP）
- 没有任何参考视频、关键帧或姿态图——纯文字编舞没有任何可迁移来源，拒绝并转交 `h3-prompt-writing` 的 T2VA
- 需要超过 15 秒连续动作且用户拒绝分段

## 2. Intake · 最小输入

分析前必须确认以下全部信息：

1. **动作参考视频**（Ref2VA 路线必需）
   - 最佳：4–15 秒、单一清晰可见的运动主体、固定或简单运镜
   - 超过 15 秒：请用户选择 ≤15 秒的片段，或规划分段
   - 确认用户拥有使用权；不接受用于冒充真人的私人 footage
2. **目标主体**（必需）
   - 角色 / 吉祥物 / 产品的参考图，或精确文字描述
   - 若目标体型与参考主体差异大（如团子吉祥物 vs 人类舞者），现在就要记录——它决定可行性
3. **输出格式**——画幅（16:9 / 9:16 / 1:1 / 4:3 / 3:4 / 21:9）与时长（4–15 秒，默认与参考窗口一致）
4. **相机策略**——`固定机位`（默认，推荐）或 `复制参考运镜`
5. **场景策略**——默认简洁中性场景；复杂场景会吃掉动作保真度
6. **音频策略**——无声 / 仅音效 / BGM 方向；是否参考原视频的音频节奏

用户没有参考视频时，走第 7 节的兜底模式，并明确告知动作保真度会显著下降。

## 3. Goal · 最终目标

交付**一条通过验收的视频**（或一条通过验收的分段链）：

- 目标主体可辨识地表演参考动作，时机与节奏一致
- 目标身份在每一帧保持稳定
- 身体力学符合目标比例，自然无 glitch
- 画幅、时长、相机与音频策略与 intake 确认一致

验收优先级：动作保真第一，身份稳定第二，其余第三。

## 4. Analysis · 先分析后动笔

写任何提示词之前，输出简短分析块：

**参考视频：**

- 动作类别：全身舞蹈 / 上半身手势 / 移动走位 / 面部表演 / 纯运镜
- 主体取景：全身 / 半身 / 特写
- 节奏：慢 / 中 / 快；节奏平稳还是重音驱动
- 遮挡、道具、与物体或他人的交互
- 相机：固定 / 摇镜 / 跟拍 / 环绕；动作占画面比例

**复杂度分级：**

- **S 级**——慢速、单平面、无遮挡（挥手、点头、摇摆、慢走）→ 单次生成，最长 15 秒
- **M 级**——多肢体协调、中等节奏（舞蹈乐句、跳跃落地）→ 单次生成，建议 ≤10 秒
- **L 级**——旋转、快速脚步、特技、严重遮挡 → 拆成 2 段以上、每段 ≤8 秒，或请用户简化

**目标主体：**

- 与参考主体的体型兼容性（类人 / 四足 / 物体）
- 必须在每帧存活的 3–5 个身份锚点（轮廓、配色、标志性道具）
- 参考动作中对目标身体不可行的部分——现在就标记

**结论：** 一段话说明迁移方案：可行 / 简化后可行 / 不可行，以及原因。

## 5. Planning · 制作规划

把分析转化为制作计划：

1. **动作节拍表（Motion Beat Sheet）**——把参考动作切成 1–4 个带时间码的节拍，如 `0.0–2.5s：重心左移、双臂上举；2.5–5.0s：旋转……`。一个节拍 = 一个可读动作。每 15 秒不超过 4 拍。
2. **时长**——与参考窗口一致，限制在 4–15 秒。M 级 ≤10 秒；L 级每段 ≤8 秒。
3. **画幅**——全身动作用 9:16 或 16:9；上半身手势用 1:1 / 3:4 / 9:16；运镜复制与参考视频同比例。所选比例不得裁掉运动中的身体部位。
4. **相机**——默认固定机位。只有当运镜本身就是需求核心时才复制参考运镜。
5. **场景**——默认中性摄影棚 / 干净背景。丰富场景是用动作保真度换来的，用户提出时要说明这一点。
6. **分段**——L 级或 >15 秒：在动作停顿处切开，规划尾帧续接（A 段最后一帧作为 B 段首帧参考）。

## 6. Intermediate Artifacts · 中间产物

生成前，以下产物对用户可见：

- **动作节拍表**——第 5 节的带时间码节拍列表
- **目标主体卡**——身份锚点；用户没给图时，先生成一张目标静帧并锁定
- **迁移简报（Transfer Brief）**——一小段话：*什么在动*（参考动作）、*谁来表演*（目标主体）、*保留什么*（时机、节奏）、*改变什么*（主体、场景、风格）、*相机与音频策略*
- 可选：计划 FL2VA 混合路线时的首/尾帧静帧

用户确认迁移简报后才开始生成。

## 7. H3 Strategy · 模式选择

按手中素材选择生成模式，优先级如下：

| 手中素材 | 模式 | 说明 |
| --- | --- | --- |
| 参考视频 + 目标图片 | **Ref2VA**（主路线） | 动作保真度最高。动作作为来自 `<Video 1>` 的 `<Subject N>` 动作属性进入，保留标记用 `attribute_transfer` |
| 参考视频 + 纯文字目标 | **Ref2VA** | 结构相同；目标主体在 `subject_definitions` 中用文字定义 |
| 目标图片 + 文字动作描述（无视频） | **I2VA** | 动作靠文字描述，保真度取决于描述质量 |
| 起始姿态 + 结束姿态两张图 | **FL2VA** | 单镜头；描述两姿态之间的动作路径 |
| 仅结束姿态图 | **L2VA** | 少见；用于「必须精确落到这个结束姿势」 |
| 纯文字、无任何素材 | **拒单 / 转交** | 非迁移任务——无可迁移来源，转交基础 `h3-prompt-writing` T2VA |

长/复杂动作的分段：每段运行 Ref2VA，主体定义保持一致；上一段验收后的尾帧作为下一段的 `<Picture N>` 首帧锚点（Ref2VA + keyframe 混合路线）。

一次生成绝不混用两段参考视频——一次一个动作来源。

## 8. Prompt Construction · 提示词构建

所有提示词按 `h3-prompt-writing` 规则书写。主路线 Ref2VA：

1. **`subject_definitions`**——一个 `<Subject N>` 定义目标（外观来源：`<Picture N>` 或文字），另一个 `<Subject N>` 定义*动作本身*、来源于 `<Video 1>`，如 `<Subject 2> is the dance routine performed in <Video 1>, including its step sequence, timing, and tempo.`
2. **`summary`**——前缀 `[reference generation]`；说明谁表演什么、各来自哪个标签。
3. **`retention_analysis`**——目标外观：`fully_preserved`；动作：`attribute_transfer`（从参考表演者转移到目标）；需要复制运镜时，为 `<Video N>` 单列一条，其相机路径与节奏标 `fully_preserved`。
4. **`detailed_description`**——先写 1–2 句风格句，再写 `[Shot 1]`（不带时间戳）。把动作节拍表写进镜头描述，带显式时间码，每拍点名动作来源（"following `<Subject 2>`..."）。在第一个镜头声明相机策略。生成类任务 350–500 英文词。
5. **`overall_soundscape` / `non_diegetic_music`**——按音频策略填写；不用则 `N/A`。
6. 语言规则：各段落用英文；对白 / 歌词 / 画面文字在 `<d>` 或引号内保留原文。

兜底模式遵循 `base-en.txt`：I2VA / FL2VA / L2VA 以精确的关键帧对齐指令行开头，随后按顺序写三个核心字段。

各模式、画幅、时长的可直接运行 Prompt 见 [`references/prompt-library.md`](references/prompt-library.md)。

## 9. Generation · 生成

- 模型：**MiniMax H3**。时长 = 计划窗口（4–15 秒），比例 = 计划比例。
- 首遍用默认分辨率（短边 768px）。动作通过验收后，需要 2K 再用 H3-Regenerate-2K 升级。
- 计划中包含音效/BGM 时开 `generate_audio=true`；`non_diegetic_music` 中的音乐方向与参考节奏保持一致。
- 每个计划分段生成一次；不要整条链批量多变体重抽。
- 每次重试只改一个变量（见第 11 节）。

## 10. Review · 验收清单

交付前逐项检查：

- **动作保真**——参考动作可辨识；节拍表中每一拍按序出现；节奏一致
- **覆盖度**——没有节拍被悄悄丢弃；最后一拍落在视频时长内
- **身份**——目标锚点每帧稳定；参考表演者的特征没有泄漏到目标身上
- **身体完整性**——无多肢、关节熔化、肢体冻结、服装突变
- **相机策略**——该固定的固定了；该复制的路径一致
- **场景纪律**——背景没有抢占运动身体的细节预算
- **音频**——符合约定策略；音乐节奏与动作匹配

每项打分：通过 / 部分通过（指出失败节拍）/ 失败。部分通过或失败 → 带原因进入第 11 节。

## 11. Retry Strategy · 重试策略

先修最便宜的一层。失败绝不整套重写。

| 症状 | 第一修复 | 进一步 |
| --- | --- | --- |
| 动作被忽略或变成通用动作 | 在 `retention_analysis` 写清迁移内容（步伐顺序、时机、节奏）；把第 1 拍写进 `[Shot 1]` 首句 | 缩短时长；减少节拍 |
| 节拍间时机漂移 | 给每拍加显式时间码 | 减少节拍数；缩短时长 |
| 目标身份中途漂移 | 给目标的 `<Subject N>` 加 1–2 个更强身份锚点 | 把目标图作为 `<Picture N>` 关键帧锚点（混合路线） |
| 肢体熔化 / 多肢（L 级动作） | 在动作停顿处分段；场景简化为纯色背景 | 请求同套动作的慢速版本 |
| 该固定的相机动了 | 在镜头描述中加入 "The camera holds a static shot throughout" | — |
| 场景抢戏 | `detailed_description` 中把场景削成中性背景 | — |
| 链中某一段失败 | 用同一上游尾帧**只重生成该段** | — |

同一层两次重试失败后升级给用户：提供简化选项（更短窗口、更少节拍、更简单动作），不要第三次盲抽。

## 12. Output · 交付内容

一并交付：

1. 最终视频文件（分段链按顺序排列）
2. **动作节拍表**与**迁移简报**
3. 最终生成所用提示词原文（可复用资产）
4. 设置记录：模式、画幅、时长、音频策略、分辨率遍数
5. 验收备注，含已接受的妥协项（如「第 3 拍在第 2 次重试后简化」）

## 边界

本 Skill 迁移的是*动作*，不是身份：不把参考表演者的脸、身体或肖像复制到目标身上；绝不用它让真实私人做出其未做过的动作。纯风格迁移、视频剪辑或不接受分段的 >15 秒需求，请路由到相应工作流，不要硬用本 Skill。
